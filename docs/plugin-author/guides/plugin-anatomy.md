# Plugin anatomy

A plugin has a source tree, a manifest contract, and a generated distribution. The CLI validates and
packages the source; the host loads the files emitted by `mndw pack`.

```text
my-widget/
  manifest.json          # plugin identity and runtime contract
  package.json            # workspace metadata, scripts, and build dependencies
  src/
    index.ts              # source entry; exports createInstance
    App.svelte            # optional framework component
  i18n/
    en.json               # catalog referenced by manifest.json
  backend/
    main.sh               # optional declared exec command
  src/*.test.ts           # author-side tests; not runtime entry files
  dist/                   # generated by mndw pack; do not edit
    manifest.json
    index.js
    index.css              # emitted when the frontend produces CSS
    mndw.lock.json
    mndw-artifact.json
    backend/main.sh        # only when declared by the manifest
```

The exact source files vary by framework. `manifest.json` is the runtime contract; `package.json`
helps the repository and CLI build the source. The default production source entry is `src/index.ts`,
while `manifest.json` names the packaged entry, commonly `index.js`. The entry must export
`createInstance(container, context)` and return an instance with `unmount()`.

Keep tests, source maps, and development-only helpers out of the runtime contract. The packer stages
the frontend bundle, manifest, lock and artifact metadata, referenced locale catalogs, and declared
backend commands. Generated `dist/` and ZIP files are ignored by the repository. See the
[lifecycle guide](/guides/frontend-lifecycle), [manifest guide](/guides/manifest), and the complete
[Hello widget tutorial](/tutorials/hello-widget).

Useful source references: [`hello-widget`](https://github.com/Eralde/mndw/tree/main/plugins/examples/hello-widget)
and [the plugin system contract](https://github.com/Eralde/mndw/blob/main/docs/plugin-system.md).
