# go-blanklr

Переформатировщик после `gofmt`: он вставляет пустые строки между соседними операторами Go
разных семантических классов, имитируя правило ESLint
`padding-line-between-statements` репозитория для TypeScript.

`gofmt` обрабатывает отступы и выравнивание, но не задаёт правила пустых строк. В Go нет
аналога ESLint. `go-blanklr` закрывает этот пробел.

## Политика

Каждый оператор относится к одному из следующих классов:

| class     | statements                                                            |
| --------- | -------------------------------------------------------------------- |
| `assign`  | `AssignStmt`, `IncDecStmt`, `SendStmt` (`ch <- v`), объявления `var`/`const` |
| `call`    | `ExprStmt` (вызовы, получения, отдельные выражения)                  |
| `control` | `if`/`for`/`range`/`switch`/`type-switch`/`select`/`return`/`break`/`continue`/`goto`/`fallthrough`/`defer`/`go`/`{}` без имени/объявление типа; `LabeledStmt` классифицируется по вложенному оператору |
| `case`    | заголовки условий `case`/`default`/`comm` (группируются друг с другом) |

Пустая строка вставляется между двумя соседними операторами, **если только** они не принадлежат
одному классу, который допускает группировку:

- `assign` → `assign`: пустой строки нет (последовательность присваиваний можно группировать);
- `call` → `call`: пустой строки нет (последовательность вызовов можно группировать);
- `case` → `case`: пустой строки нет (условия группируются);
- всё остальное: **пустая строка**.

### Исключение для проверки ошибок

Идиома Go `x, err := f(); if err != nil { … }` **не разделяется**: присваивание и следующая
проверка ошибки считаются одной семантической единицей, поэтому между ними нет пустой строки,
хотя обычно для `assign → control` она нужна. Конструкция распознаётся, когда `prev` —
`AssignStmt`, присваивающий идентификатору с именем `err`, а `cur` — следующий `IfStmt`, чьё
условие использует `err` (сюда входят `err != nil`, `err == nil`, `errors.Is(err, …)` и составные
проверки). Для присваивания не-`err` с последующим `if` (`x := f(); if x > 0`) пустая строка
по-прежнему вставляется.

Это единственное правило кодирует матрицу ESLint:
`*: if/for/switch/try` + `if/for/switch/try → *` (управляющие конструкции всегда разделяются),
`const/let/var → const/let/var` — `any` (группируются), `*: return` (`return` — управляющая
конструкция), а также разделение assign↔call.

`case` — отдельный класс группировки, поэтому ветви `switch`/`select` **не** разделяются
принудительно; обрабатываются только операторы внутри каждой ветви.

## Алгоритм

1. Отформатировать файл с помощью `gofmt` (канонизировать пробелы и выравнивание, чтобы номера строк были стабильными).
2. Выполнить синтаксический разбор с комментариями.
3. Обойти каждый `BlockStmt`, `CaseClause.Body`, `CommClause.Body` (и верхнеуровневые `Decls` с `--top`). Для каждой пары соседних операторов, между которыми нужна пустая строка, записать целевую строку.
4. Целевая строка — фактическое начало оператора, включая группу ведущих комментариев между предыдущим и текущим оператором, чтобы вставленная пустая строка не отделила `// comment` от его оператора.
5. Вставить пустые строки (начиная с самых больших номеров строк, чтобы сохранить прежние индексы).
6. Снова выполнить `gofmt`. `gofmt` не удаляет одну пустую строку между операторами, поэтому результат идемпотентен.

## CLI

```
go run ./tooling/go-blanklr [flags] path [path...]
```

| flag     | behavior                                                       |
| -------- | ------------------------------------------------------------- |
| (none)   | вывести переформатированный исходный код в stdout             |
| `-w`     | записать результат обратно в файл(ы)                          |
| `-l`     | перечислить файлы, форматирование которых изменится           |
| `--check`| перечислить изменившиеся файлы и завершиться с ненулевым кодом (режим CI) |
| `--top`  | также разделять верхнеуровневые объявления (func/type/var/const/import) |

Путями могут быть файлы или каталоги; каталоги обходятся рекурсивно (`testdata/`, `vendor/` и
каталоги, начинающиеся с точки, пропускаются).

> **Примечание:** модуль использует только стандартную библиотеку и включён в `go.work` репозитория, чтобы `go run ./tooling/go-blanklr` и `go test ./tooling/go-blanklr/...` разрешались из корня репозитория. Он не имеет зависимостей, и ничего его не импортирует, поэтому он не влияет на сборки демона/плагинов или `go work sync`.

## Подключение

### Скрипты pnpm

```bash
pnpm fmt:go                         # записывает — корни daemon/packages/plugins по умолчанию
pnpm fmt:go -- daemon/mndwd         # записывает — только этот каталог Go
pnpm fmt:go:check -- daemon/mndwd   # CI — проверяет только этот каталог Go
```

При явных путях скрипты заменяют корни по умолчанию, а не добавляют к ним новые. Скрипты корня
передают обработку аргументов в `build/fmt-go.sh`. Поддерживаются формы `pnpm fmt:go path` и
`pnpm fmt:go -- path`. Обе используют локальный `GOCACHE` репозитория для воспроизводимости в
песочнице.

### Pre-commit (необязательно)

В репозитории нет husky/lefthook. Для локальной проверки добавьте этот файл в
`.git/hooks/pre-commit` и выполните `chmod +x`:

```sh
#!/usr/bin/env sh
cd "$(git rev-parse --show-toplevel)"
pnpm fmt:go:check
```

Либо вручную добавьте файлы в индекс и запустите `pnpm fmt:go`.

## Ограничения и вкусовые решения

- Привязка комментариев определяется только позицией (комментарии между двумя операторами относятся к следующему оператору). Док-комментарии у объявлений не переформатируются; выполняется только вставка пустых строк.
- Для `--check` нет автоисправления; выводятся только изменившиеся файлы. Исправление выполняет записывающий проход `pnpm fmt:go`.

## Тесты

```bash
GOCACHE=<repo>/.cache/go-build go test ./tooling/go-blanklr/...
```

Покрываются: матрица политики, исключение для проверки `err` (объединённая, `errors.Is`,
составная и отрицательная проверка для не-`err`), привязка комментариев (ведущих и завершающих),
вложенные блоки, ветви switch/select, идемпотентность, `--top` и таблица модульных тестов
классификатора.
